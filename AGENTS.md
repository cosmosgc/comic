# Comic — project guide

A comic-sharing social site: comics, collections, social posts, a forum, gamification, an E-Hentai importer, and an FTPS deploy panel. Laravel 12 / PHP 8.5, Blade + Alpine, Tailwind v4 through Vite. **The UI, comments, and `Docs/*.md` / `changelogs/` entries are Portuguese — keep new user-facing text and changelog prose in Portuguese.** The block below is generated by Laravel Boost; `php artisan boost:update` rewrites only that block, so everything above it is safe to edit.

## Commands

- Dev: `_start.bat` (runs `npm run dev --host` + `php artisan serve`). There is **no `composer run dev`**.
- Build assets: `npm run build` (`_Build.bat`).
- Local DB: `_Migrate.bat [--fresh] [--seed] [--rollback]`, or `php artisan migrate` directly.
- Format: `vendor/bin/pint --dirty`. There is **no `pint.json`** (defaults). Don't run Pint on files you didn't touch — it reformats untouched lines and especially `routes/web.php` (PR checklist calls this out).
- Test one class: `php artisan test tests/Feature/SomeTest.php` or `php artisan test --filter=test_name`. Unit tests live in `tests/Unit`, feature tests in `tests/Feature`.

## Test database — the big gotcha

`phpunit.xml` does **not** force sqlite (those `DB_CONNECTION`/`DB_DATABASE` lines are commented out), so tests default to the `.env` **MySQL** database unless a test opts out. There is **no `RefreshDatabase` trait**. Each suite class must isolate itself in its own `setUp()`:

```php
config(['database.default' => 'sqlite']);
config(['database.connections.sqlite.database' => ':memory:']);
$this->artisan('migrate');
```

Follow that pattern for new tests or they run against (and can wipe) the dev database. A few classes intentionally hit the real DB and `markTestSkipped()` when no seeded user exists: `ChangelogTest`, `ComicUploadLimitsTest`, `DeployPanelTest`.

## Repo conventions worth knowing

- **Changelogs:** a user-visible change gets one JSON file in `changelogs/` (id `YYYY-MM-DD-slug`; schema and validation in `App\Services\ChangelogWriter`; fields `pr`, `title`, `date`, `category`, `tags`, `summary`, `body`), categories `Added|Fixed|Changed|Removed`, plus a bullet under `Docs/CHANGELOG.md`. Managed in-app at Admin → Novidades and shown at `/changelog`.
- **User uploads** are written straight into the real `public/storage/` directory (a plain, gitignored directory — **not** a symlink), using `App\Support\ImageStore` with random names. Don't move user media to `Storage::disk('public')->store()`; that disk is only used for forum attachments.
- **`public/build/` is gitignored.** Run `npm run build` after any CSS/JS change and include compiled assets in the deploy, or the host serves stale chunks.
- **Livewire was deliberately removed** (it was unused). Don't reintroduce it without approval.
- No CI workflows exist; `.github/` only holds the PR template.

## Deploy (host has no console)

- Push code over FTPS with `php artisan deploy:host` (or the Admin → Deploy panel). Config and the upload excludes live in `config/deploy.php`; it skips user uploads, `vendor/` (unless `--with-vendor`), `tests/`, and `Docs/`.
- Migrations run on the host from Admin → Migrations (`POST /admin/migrations/run`), not from a console.

## Layout

- Controllers in `app/Http/Controllers` (`Admin*`, `Forum*`, `Comic`, `Collection`, `Post`, `Profile`, ...); domain services in `app/Services` (`Deploy/**`, `EhComicImporter`, `Changelog*`, `Gamification`, `MigrationInspector`); helpers in `app/Support` (`ImageStore`, `Markdown`, `DescriptionText`, `PostText`). Authorization is largely inline owner-or-admin checks in controllers (FormRequests/Policies refactor still open — see `Docs/issues.md` #9).
- Views: Blade layouts `resources/views/layouts/{app,admin-layout,forum-layout}.blade.php`; Vite entries `resources/js/app.js` and `resources/js/admin.js` (the latter bundles jQuery/DataTables/Chart.js/D3 as globals for admin pages).
- Open work and architecture notes: `Docs/issues.md`, `Docs/suggestions.md`, `Docs/TODO.md`, `Docs/TODO-database.md`, `Docs/style-changes.md`.
