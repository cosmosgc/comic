## Critical — Security / Authorization

1. **[FIXED 2026-10-12] Comic/Page mutation routes now require `auth` + owner-or-admin.** `routes/web.php` — `comics.create/store/edit/update`, `reorderPages`, `pages.deletePage`, `pages.addPage/store`, `comics.setCover` all carry `->middleware('auth')`. Controllers enforce ownership via `authorizeComicAccess()` (`ComicController`, mirrored in `PageController`): owner or `admin_level >= 1`, else 403; legacy comics with null `user_id` are admin-only. `deletePage` 404s on orphan pages.
2. **[FIXED 2026-10-12] `admin.widgets.*` now behind `AdminMiddleware`.** The whole admin group (widgets included) runs under `['auth', AdminMiddleware]` — no more per-route checks to forget. Covered by `ComicAuthorizationTest::test_non_admin_cannot_access_widgets`.
3. **[FIXED 2026-10-12] Admin routes use `AdminMiddleware` + controller group.** `routes/web.php` — the ~180 inline closures became `Route::prefix('admin')->middleware(['auth', AdminMiddleware::class])->controller(AdminController::class)->group(...)` with direct action references (service DI now resolves in controller methods). Non-admins redirect to `/` as before (`ChangelogAdminTest` still green).
4. **[FIXED 2026-10-12] `TrackPageView` registered as dead expression.** `bootstrap/app.php` contained a bare `\App\Http\Middleware\TrackPageView::class;` no-op statement. Fixed to a proper middleware alias (`track.views`) with ordered imports, so it is available without silently enabling per-request analytics writes. Note: enabling it globally would cause write amplification + PII retention (`ip`, `user_agent`, full URL) — keep opt-in + sample/queue if ever enabled.
5. **[FIXED 2026-10-12] Analytics API hardened.** `AnalyticsController@store` ignores client-supplied `user_id`/`ip_address` (uses `Auth::id()` + `$request->ip()`), all fields have `max:` caps, `duration` bounded; `POST /api/analytics` throttled (`throttle:60,1`); `referralAnalytics()` capped at 5000 rows. Guest page-view tracking still works (no `auth` added by design). Covered by `ComicAuthorizationTest::test_analytics_ignores_forged_identity`.
6. **[FIXED 2026-10-17] File uploads hardened: generated names, `0755`, no orphaned files.** New `App\Support\ImageStore` moves every user upload with a random name (`bin2hex(random_bytes(12))`) whose extension comes from the **detected MIME type** — the client filename is never used, which kills `time().'_'.name` collisions, path traversal (`../../evil.jpg`) and `.php` double extensions. Folders are created `0755` (was `0777`) and only when missing. Wired into `ComicController@store` (the duplicated `folder[]`/`images[]` loops merged into one), `PageController@store`/`addPage`, `ProfileController@update` (avatar **and** banner now delete the replaced file — the old avatar was leaking) and `PostController@store`. Rules tightened: post media `array|max:4` + `image|mimes:jpeg,jpg,png,gif,webp|max:4048`; avatar/banner gained `mimes` + generous `dimensions:max_width/max_height` caps. Covered by `tests/Feature/UploadSecurityTest.php` (8 tests: generated names, traversal name, double extension, non-image, avatar/banner replacement deletion, post media). Deliberately left alone: `Storage::disk('public')`/`store()` — user media lives in the real `public/storage/...` directory on this deployment (a directory, not a symlink to `storage/app/public`), so writing there directly is what keeps existing files/URLs working; the `public` disk stays for forum attachments, which already use `store()` + hashed names.
7. **[FIXED 2026-10-17] Mass-operation validation tightened.** Done: `reorderPages` validates `*.id`/`*.page_number`, scopes updates to the parent comic, runs in a transaction; collection `store`/`update` validate `comics.* => exists:comics,id` (`addComic`/`removeComic` were already safe via route-model binding); tag sync shared via `syncTagsFromString()` (empty fragments skipped, `tags` capped at 2000 chars, absent key preserves tags); new `GET /api/tags` autocomplete powers the pill editor. Follow-up 2026-10-17: `PostController@store` media now `array|max:4` + `image|mimes:jpeg,jpg,png,gif,webp|max:4048` with generated names (see #6), and the `ComicController@store` slug is no longer trusted verbatim — it is validated (`nullable|string|max:255`), re-slugged and de-duplicated through `Comic::generateUniqueSlug()` (which now also falls back to `comic` when a title has no slug-safe characters), so a duplicate/invalid slug can no longer 500 on the unique index. Covered by `tests/Feature/ComicSlugTest.php` (5 tests). Follow-up 2026-10-18: `CollectionController@store`/`update` now validate `comics.*` in the same `validate()` call that guards the rest of the payload, so a bogus id can no longer leave a partially written collection behind (create used to save first, update used to rename first); covered by `CollectionTest::test_bogus_comic_ids_are_rejected_on_collection_store` and `test_bogus_comic_ids_do_not_half_update_a_collection`.
8. **[FIXED 2026-10-18] `phpinfo` removed; remaining admin tools verified admin-only.** The `/admin/phpinfo` route, `AdminController@phpinfo`, and `admin/phpinfo.blade.php` are deleted. The deploy + migration-run panels stay **by design** (documented admin-only tools) and are now covered by `tests/Feature/AdminPanelAuthorizationTest.php`: guests are sent to `/login` and non-admins redirected to `/`, for both the panels and the POST endpoints that mutate the host (`/admin/migrations/run`, `/admin/deploy/run`, `/admin/import`, `/admin/import/preview`).
